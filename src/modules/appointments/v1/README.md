# Appointments foundation

Customer-only `POST /api/v1/appointments` accepts `{ doctorId, startsAt }` and automatically confirms an exact available slot. `GET` on the collection returns only the authenticated customer's paginated history (`doctorId` and `status` filters); `GET /:id` returns their appointment or `404`. Identity and branch/timezone/duration/decimal price/currency snapshots are derived by the service. Other input fields are rejected.

The shared generator serves public doctor availability and transactional booking rechecks. Windows include today through +90 branch-local days; availability requests require `from` and `to` and cover at most 31 dates. Slots follow interval starts and current duration, with dated exceptions overriding weekly hours. Uncertain or clock-transition-crossing slots are omitted. UTC timestamps require seconds and an explicit offset, with up to millisecond precision. No minimum notice, buffers or holds exist. Public availability excludes doctor bookings; booking also checks customer conflicts. Duplicate/stale requests return localized `409`.

Migration 005 adds doctor and customer exclusion constraints for non-cancelled `[start,end)` ranges using `btree_gist`. Booking locks customer, doctor and related eligibility records; existing schedule writes share the doctor lock. Schedule/profile changes never rewrite booked snapshots. Cancellation, rescheduling, staff actions and notification/payment workflows remain unimplemented.
