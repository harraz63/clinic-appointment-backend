# Doctor management

Doctor profile belongs to one account, branch and specialty. Admin routes create verified doctor-role accounts and profiles atomically, list and read profiles with their account/branch/specialty, update profile fields, and deactivate without deleting history. Lists support bilingual profile-name search, branch/specialty filters, activity filters, and pagination. Assignments and reactivation require an active branch and specialty. Generic user management cannot create/promote doctor accounts or demote/delete accounts linked to doctor profiles.

Admin routes are mounted under `/api/v1/admin/doctors`. Creation requires an Egyptian phone, account name, strong initial password, bilingual profile name, branch, specialty, decimal appointment price, and positive duration; currency defaults from `CLINIC_CURRENCY`. Branch reassignment requires first clearing saved hours and exceptions.

Public `GET /api/v1/doctors` supports `search`, `branchId`, `specialtyId`, `isAvailable`, `page` and `limit`; `GET /:id` returns an explicit public projection. Eligibility requires active profile/branch/specialty and an unblocked doctor-role account. Account phone, credentials and administrative flags are excluded. Unavailable doctors remain visible. `GET /:id/availability?from=YYYY-MM-DD&to=YYYY-MM-DD` returns timezone, duration and date-grouped UTC slots. Booking is customer-only under `/api/v1/appointments`. See [the clinic foundation](../../../../CLINIC_FOUNDATION.md) for access rules and [appointments](../../appointments/v1/README.md) for slot rules.
